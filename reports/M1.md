## Deviations from the spec, and why

1. **`instrumental_flag`, `max_chars`, `recipe` are keyword arguments of `compile()`**, not plan fields. The plan schema has no instrumental flag (section 7), so "wordless + instrumental flag" is exercised through `compile(plan, instrumental_flag=True)`. A real lead can never exceed 512 alone, so "lead alone > cap -> OverBudget" is tested by lowering the cap with `max_chars` (it can only be lowered). The 6-beat over-budget case passes a synthetic recipe dict through `recipe=`.
2. **Supports `role` also accepts `"lead"`** (a second claim to lead) so the "two leads" conflict can be expressed; the compiler demotes it to `answer`. Not in the section 7 enum.
3. **Plan defaults**: most fields default (150 s, medium 88 BPM, D major, slow_build, balanced, 3 takes); only brief, voice_mode and lead are required. Sung requires `lyrics.policy` write or exact; `exact` requires text; supports may not repeat an instrument; duration is 10-240 (matches the M0 engine validator).
4. **Lyrics text for sung with policy `write` and no text raises `LyricsMissing`** instead of guessing. Under Basic the planner reports `write_lyrics` unsupported and `needs_user_input: ["lyrics"]`.
5. **R1 pace bucket is `medium`**: 82 BPM falls in the C8 medium bucket (80-96), not slow. R2 medium (88), R3 slow (76), R4 lively (104).
6. **R3 lead instrument is the fingerpicked guitar** (the plan needs an instrument id); the lead-priority sentence for sung mode says the voice leads. R3's accepted Hindi lyric lives in the recipe as `example_lyrics`; `plan_from_recipe` leaves lyrics as `write`/no text (so the planner never silently reuses Thodi's words for a new brief); `default_plan()` includes them (used by the golden tests).
7. **R4 default has 4 supports** (tabla, ghatam, santoor, violin), not Moonlit's seven instruments, because the lead sentence plus 7 instruments cannot fit 512. Recorded in the recipe caveat. R4 stays hidden.
8. **The drop order is applied literally**: all optional supports go before any technique term. That would have stripped the supports from R2 and R4, so those two recipes carry shorter tone/technique/arc wording (recipe overrides) so their defaults compile with nothing dropped. R1-R3 and R4 defaults all compile with `dropped == []`.
9. **Flavour clause is rendered last (after the tail)**, exactly as slot 8 reads. The accepted captions have no flavour, so this has no listening evidence either way.
10. **Compile output also carries `effective_params`** (= params with `guidance_scale` 1.0). Requested `guidance_scale` stays 7.0 to match the preserved requests. The effective value is the expected turbo override, not a measurement: the engine's `result.json` is authoritative.
11. **Tag insertion heuristic** (not in the spec): stanzas repeated verbatim become `[Chorus]`, others `[Verse]`; with no repeats the tags alternate Verse/Chorus. Inserted lines are always reported by index. If the user wrote any `[Tag]` line, nothing is inserted.
12. **"More melodic" chip** adds the feeling word `memorable`, which the compiler turns into "Memorable recurring melody" (there is no separate field). **"Less busy"** relies on the `spare` fullness phrase ("Sparse accompaniment with breathing space.") for the section 6 tail.
13. **Basic planner defaults** (not specified): no voice words -> instrumental; sung with no language cue -> Hindi (the only sung language heard), with a note; named supports are topped up from the recipe to at least two unless the brief says just/only/solo; first melodic instrument leads unless a lead cue ("solo", "led by", "main") is next to another.
14. `to_engine_request` also accepts optional `audio_format` and `meta` keyword arguments because the M0 contract has those top-level keys; with neither given it returns exactly `{schema, params, seeds}`. Seeds are validated as 1-8 distinct ints in [0, 2^31) to match M0.
15. No `conftest.py` (not in my file list): each test file inserts `app/` on `sys.path` and imports `backend.*`. Backend modules use relative imports, so M2 can import them as `backend` (run from `app/`) or `app.backend`.

- Under Basic, sung briefs cannot compile until the user pastes lyrics (`LyricsMissing`). M2/M3 must surface `card.needs_user_input` and `card.unsupported` rather than calling compile blindly.
- `compile_report` extras beyond the spec: `unsupported`, `notes`, `cap`, `slots` (ordered `[slot, text]` pairs for the plan view), `lyrics` (hashes, inserted tag indices, fit result).
- `copyright_policy` is rule-based name stripping with a cue list; it cannot recognise a bare title with no cue ("play Tum Hi Ho"). It is not clearance. User exact lyrics are deliberately untouched.
- Roman Hindi and Devanagari matching is keyword-level and NFC-normalised; it will miss spellings not in the alias lists. Extend `INSTRUMENT_ALIASES`, `MOODS`, `PACE_WORDS` in `planner_rules.py`.
