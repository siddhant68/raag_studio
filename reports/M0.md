## Deviations and things the orchestrator must know

1. **ACE auto-download quirk (changes the plan slightly).** ACE's `check_main_model_exists` requires the 5Hz LM folder `acestep-5Hz-lm-1.7B`, which the plan deliberately does not install. So the unmodified call path (every historical script and `scripts/render_local.py`) makes `initialize_service` do: a TCP probe of www.google.com:443 (log: "Auto-detected: HuggingFace Hub"), a `snapshot_download` attempt to `ACE-Step/Ace-Step1.5` that fails offline ("Returning existing local_dir ... as remote repo cannot be accessed"), and `shutil.copy2` of `modeling_acestep_v15_turbo.py` and `configuration_acestep_v15.py` into `checkpoints/acestep-v15-turbo/`. I saw this in the engine.log of the second of my two aborted pre-patch runs (the first took the same code path), so each of those loads made one Google TCP connection and rewrote the two code files with identical content and preserved mtime (still Oct 22 19:51:22; all 16 checkpoint sizes still equal the inventory). No weights were downloaded. `run_takes.py` now patches `init_service_downloads.check_main_model_exists` in-process and refuses non-loopback TCP, recording attempts. `scripts/render_local.py` still has the unguarded behaviour (not mine to edit). Any other ACE caller, including a future M2 worker that does not go through `run_takes.py`, should do the same.
2. **FLAC works, and is 24-bit; the engine's WAV is 16-bit.** Contract: native audio is FLAC by default. FLAC of the 168 s take is 25 MB vs 32.3 MB for 16-bit WAV vs 48.4 MB for 24-bit WAV. The WAV figures are from re-encoding the FLAC samples, not from a WAV render (budget); the engine WAV writer's bit depth was confirmed on a synthetic tensor.
3. **Request contract details the M1/M2 authors need** (full text: `app/engine/REQUEST_CONTRACT.md`): top-level `schema`, `params` (no `seed`), `seeds` (1 to 8), optional `audio_format` and `meta`; unknown params rejected; `task_type` text2music only; duration 10 to 240; `take_done.path` is **relative to the OUT_DIR** because the caller renames `.partial`; files are named `take_NN_s<seed>.flac`; exit codes 0/1/2/3/4/143. Recipes should send `guidance_scale: 1.0` (7.0 is accepted and recorded as requested 7.0 / effective 1.0).
4. **Silence check is fragile.** Take A1 has a 7.6 s sub -50 dB tail (the last 7.6 s, includes the 3 s fade-out) = 4.52% of 168 s, a 0.5 point margin. PRD 9 does not define the silence floor; I used -50 dB, minimum 0.5 s. The accepted Yamuna MP3 gives 2.5% by the same measure. A 60 s track with a 3 s tail would sit at exactly 5%. M2 must fix the floor and decide whether the fade-out/tail is excluded or trimmed, otherwise it will retry or flag good takes (or none).
5. **Memory is tight.** In-process peak RSS 13.8 GiB (set during model load, flat across takes and lengths), but macOS "peak memory footprint" is 51 to 55 GB on a 48 GiB machine (0 swaps). Never overlap an ACE render with a ComfyUI video job; the queue gate in PRD 9 is essential. `preflight.video_queue.state` is an object (`idle|busy|unknown`, plus counts), not a string. ComfyUI's `/queue` returns keys `queue_running` / `queue_pending` (the script accepts `running`/`pending` too).
6. **No GPU-test restrictions were hit:** MPS was available from this shell (`torch.backends.mps.is_available() == True`), unlike the "restricted shell" warning in the runbook.
7. **Left behind for sweeping:** `runs/_m0/20261023T213344Z/sigterm_loading.partial` (deliberate AT-M0-07 evidence; safe to delete). Two earlier SIGTERM test directories from the unpatched harness were deleted by me (their log lines are quoted in item 1); the same applies to throwaway files in the scratchpad.
8. `run_takes.py` uses the private ACE helper `handler._resolve_dcw_enabled` (wrapped in try/except; not fatal if it disappears) and a monkeypatch of `check_main_model_exists`. If the ACE source is ever upgraded, re-run a dry real run and read `engine.log` for "auto-download" lines.
